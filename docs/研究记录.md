# QA75QN85BAJXXZ 美区研究记录

记录时间：2026-10-31。公开版已隐藏设备专属备份摘要，并省略无关的 Hue 开发记录。电视固件 `T-PTMUABC-1651.7`，目标地区：美国。

## 已验证

- SDB 连接正常。公开工具 `samsung-tv-root` v0.0.12 的 `archive-root` 路线通过认证，获得临时 UID/EUID 0；工具报告暂存文件已清理、其检查的系统文件未改变。此结果不代表所有安全限制解除。
- 工厂 D-Bus 服务 `org.tizen.tv.factory-service` 的 `GetLocalSetStr` 对 0–53 的枚举仅成功返回 `0 = NONE` 和 `43 = CHI_DTV`。`GetLocalSetListNo` 返回 `((54, 43), (1,))`；字段语义尚未验证。
- 系统通用配置中 `db/comss/countrycode = CN`、`db/system/country = 29`、`db/system/last_region_id = 5`、`db/setting/region_automatic = True`。它们不是已确认的完整改区方法。

## 后续：工厂数据区只读副本

- 根据原厂 `FCNvramMap::ReadFactoryArea` 的范围和 `t_Read` 使用的 ioctl，使用 32 位 .NET 程序以 O_RDONLY 模式读取 EEPROM 中地址 `0x3e00` 起的 16,384 字节。先运行无设备访问的程序验证环境；实际读取了两遍，对应块使用不同初始值，结果逐字节相同。
- 本地文件 `eeprom-factory-area-original.bin` 权限为 0600，长度 16,384，SHA-256 为 `[设备备份摘要已隐藏]`。它是该 16 KiB 数据区的两次一致读取，**不是整个 EEPROM，更不是已验证能恢复的镜像**。该文件可能包含设备专属数据，应保持私密。
- 读取程序见 `eeprom-read/Program.cs`，只使用 O_RDONLY 和原厂程序中的读取 ioctl；电视端的临时程序已删除。工厂服务仍为 active，NRestarts=1。
- 离线分析 `FCControlItemExecution::t_ExecuteLocalSet` 显示 Local Set 的处理会涉及多个工厂项，以及 UID 0xbbf 的写入；不能把枚举 23 当作单个 EEPROM 字节直接写入。

## 后续：工厂数据库和过滤逻辑

- 从 `/factory_peq/factory-data` 只读复制 `Factory_Part1.dat` 和 `Factory_Part2.dat`，本机内容 SHA-256 均与电视端匹配。它们是固件的工厂数据库，不是当前 EEPROM 备份。
- 数据库将 UID 194 标记为 `Local Set`，UID 761 标记为 `Preventing Import`，均使用 `FC_STORE_LEVEL_FIXED`。索引中对应的最后字段分别是 0x23 和 0x65；工厂区备份相应字节分别是 43 和 13。43 与服务返回的国区列表索引相符；从这些结果推测这些字段可能为存储偏移，但尚未通过受控写入验证。

## 后续：64 KiB EEPROM 读取及硬件线索

- 电视设备树和 I²C 驱动显示总线 `3`、地址 `0x50` 有 `s24c512c` 设备；`/dev/eeprom` 是虚拟字符设备。尚未从实物丝印或驱动代码证明虚拟设备与该物理芯片的对应关系。
- 使用原厂程序的只读 ioctl，对地址 `0x0000–0xffff` 逐块读取两遍，逐字节一致，保存为 `eeprom-64k-original.bin`（0600）；SHA-256 `[设备备份摘要已隐藏]`。其中 `0x3e00–0x7dff` 与先前工厂区副本逐字节一致。
- 64 KiB 覆盖读接口尝试范围，不代表 eMMC、其他存储器或安全凭据全部备份；未验证物理芯片外接读写、程序写回或断电后的恢复。文件可能包含设备专属数据，不宜公开。
- 工厂服务 active，重启计数仍为 1，电视端临时读取程序已删除；系统仍报告 CN。未修改区域或重置。
- 后续获取并校验了内核模块 `tztv-eeprom.ko`：I²C `3-0050` 的 `s24c512c` 驱动由 `tztv_eeprom` 模块提供，同一模块字符串和符号包含字符设备 `eeprom`、`eep_class`、`eep_ioctl`、`eeprom_dev_read`、I²C 读写及写保护逻辑。这是两者关联的较强软件证据，但仍不是拆机核验和独立编程器读回。
- 模块包含缓存读取逻辑，因此两次 ioctl 一致也可能受同一缓存影响；不等同于两次独立的硬件编程器读取。
- 进一步反汇编 `eep_reg_read`，核实三星驱动使用两条 I²C 消息：先发送两字节地址，再读取数据。通过 `/dev/i2c-3` 的 I2C_RDWR 对地址 0x50 使用同一只读事务、每次 64 字节，完整读取两遍；两遍一致，与 `eeprom-64k-original.bin` 逐字节一致。该结果避开了 `/dev/eeprom` 驱动的缓存，但仍不等同于断电后的独立编程器读写测试。未发送 EEPROM 数据写入事务。
- 用户表示目前没有编程器或拆机维修条件。电视端临时程序及 Mac 上含备份的临时结果文件已删除，工厂服务仍为 active、NRestarts=1。

- `TIFSDaemon` 的私有可执行映射可通过 `/proc/<pid>/mem` 读取；本固件内 `0x703a8` 的实际指令字节与固件文件相同，为 `0d 2b`（`cmp r3, #13`）。对该固件和当前 Preventing Import 值 13，离线模拟单次改为 `ff 2b` 可让控制枚举 23 的过滤结果从 skip=1 变为 skip=0；它还影响其他若干地区，不是只放开美国区。

- I²C 只读完整 64 KiB 两遍，哈希仍为 `[设备备份摘要已隐藏]`。它只核对该 EEPROM 读取范围，并非所有系统数据的恢复验证。
